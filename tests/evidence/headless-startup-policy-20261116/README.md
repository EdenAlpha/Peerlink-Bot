# Graphics-free startup and Android executable-memory policy

The physical-phone session exported on 2026-11-16 at 09:48:50 verified the supported engine SHA-256 and all 111 staged files (47 CPK files, 47 database tables and 44 native tables). Three startup attempts failed immediately after file preparation, before the `Starting bot simulation` status and before any match connection. The old export did not include the native operation or errno, so it cannot by itself prove which native check returned false.

The old native writer made a file-backed executable page writable, changed it, then restored execute permission. Android 15's [domain policy](https://android.googlesource.com/platform/system/sepolicy/+/refs/heads/android15-release/private/domain.te) forbids `execmod` for modern app domains. Its [app policy](https://android.googlesource.com/platform/system/sepolicy/+/refs/heads/android15-release/private/app.te) permits anonymous executable memory for application JITs. The earlier ARM64 Redroid lab reported `getenforce=Disabled`, so its successful installation did not cover this restriction.

The replacement writer prepares an anonymous writable copy of each complete affected page, applies the change, makes that copy read/execute, and atomically replaces the old mapping with `mremap`. It never writes an executable page or adds execute permission to a modified file mapping. Failed preparation/remap leaves the original mapping intact. All existing instruction checks and game changes remain the same.

Native regression checks execute a small function before/after replacement, patch across a page boundary, restore the function, compare neighboring bytes and verify that the original file is unchanged and the code is RX. The Android regression requires SELinux Enforcing by default and first verifies that the legacy file-backed write fails with EACCES/EPERM. A test-only option permits an additional ARM64 execution smoke test in the lab with SELinux disabled; that smoke test is not counted as enforcing-policy verification.

The startup export now records the failed operation, offset, errno and runtime page size. A deterministic graphics-free setup rejection is returned immediately instead of repeating the same preparation three times. The UI regression checks that a rejected startup reaches the retry/diagnostics screen. These focused tests do not prove physical-phone kickoff or a complete match.
